# Тестовое задание: Лендинг "Кварта"

## Как и для чего использовался ИИ (AI)
Проект написан с использованием Next.js, Tailwind CSS и Framer Motion. ИИ (LLM) использовался как инструмент ускорения разработки (написание boilerplate-кода, верстка сетки на Tailwind, базовая логика корзины и состояний формы).

### Где ИИ ошибался и что пришлось исправлять руками:
1. **Бэкенд на Vercel:** Изначально ИИ предложил сохранять заявки в JSON файл через модуль `fs`. На serverless-архитектуре Vercel файловая система `read-only`, что привело к падению билда (Error 1). Пришлось переписать логику API на временное хранение заявок в оперативной памяти (`memoryLeads`).
2. **Визуал:** ИИ генерировал "шаблонный" дизайн с чужими курьерами на европейских улицах, чужими брендами пачек кофе на фото и моно-капсом. Фотографии были заменены на подходящие по контексту, а иерархия кнопок была полностью переработана (второстепенные кнопки стали менее акцентными).
3. **Валидация:** Пришлось вручную "докручивать" жесткую валидацию белорусских номеров (только коды 29, 33, 44, 25, 17) как на клиенте, так и на сервере.

## Технические и бизнес-решения (компромиссы)

* **Цена подписки:** В исходных данных клиента подписка стоила 54 BYN. Однако, две пачки Колумбии/Эфиопии по отдельности стоят 52–64 BYN. Я снизил цену подписки до 49 BYN, чтобы она имела экономический смысл и реальную выгоду для покупателя.
* **Дедупликация заявок:** В `route.ts` добавлена защита от спама и двойных кликов — если с одного номера отправляется заявка чаще, чем раз в 10 минут, API отдает 429 статус. 
* **UTM-метки:** Фронтенд собирает параметры (utm_source, referrer, pageUrl и т.д.) из строки браузера и отправляет их в бэкенд вместе с заявкой.
* **Хранение данных:** Заявки сохраняются в оперативную память сервера Vercel, а также параллельно отправляются через Telegram API в личный чат администратора (с помощью настроенных переменных окружения `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`). Это решает проблему serverless-архитектуры и позволяет мгновенно получать уведомления о лидах.
* **Оптимизация изображений (Lighthouse):** В проекте используются стандартные теги `<img>` с внешними ссылками на Unsplash (1200px), что может снижать оценку Performance в мобильном Lighthouse. Интеграция компонента `next/image` с атрибутом `sizes` не была реализована из-за необходимости настраивать `remotePatterns` в конфиге для внешних доменов в рамках сжатых сроков дедлайна.
* **УНП и телефон:** Использованы заглушки (вымышленный ИП), так как проект тестовый.
